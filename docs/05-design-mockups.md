## 5.2 화면 목록과 시안 유무

하단 탭은 둘러보기 / 내 하루 / 수신함이고, 헤더 오른쪽 편지 아이콘에 미확인 수신함 점이 붙는다.

| # | 화면 | 시안 | 시안에 담긴 상태 |
|---|---|---|---|
| 0 | 로그인·회원가입 | 없음 | |
| 1 | 둘러보기 | 있음 | 이어받기 가능한 하루 카드, "취소된 하루 남기기" |
| 2 | 하루 들여다보기 | 있음 | 계획자·취소한 이유 박스, 산책 동선 타임라인, "이 하루 이어받기" |
| 2-1 | 이미 이어받은 하루 | 있음 | "이미 다른 사람이 이어받았어요" 안내 박스 |
| 3 | 사연 입력 | **없음** | |
| 3-1 | AI와 함께 정리하기 | **없음** | |
| 3-2 | 하루 남기기 (폼) | 있음 | 장소 1곳일 때, 장소 저장 후 2곳일 때 |
| 3-3 | 장소 추가 | 있음 | 장소 이름, 하고 싶었던 일, 이 장소를 고른 이유 |
| 3-4 | 공개 완료 | 있음 | "하루를 공개했어요" |
| 4 | 내 하루 (이어받음) | 있음 | 기한 문구, 동선, "다녀온 이야기 쓰기", "이어받기 포기" |
| 4-1 | 이어받기 포기 확인 | 있음 | "이 하루를 놓아줄까요?" |
| 5 | 그날의 이야기 (방문 기록 작성) | 있음 | 글, 사진 1장 첨부, "사진 없이 글로 완료" |
| 5-1 | 보내는 중 | 있음 | "사진을 준비하고 있어요", "글로 완료하기" |
| 5-2 | 사진 처리 실패 | 있음 | "사진 바꾸기" / "글로 완료하기" |
| 5-3 | 사진 교체 | 있음 | "사진을 다시 첨부해 주세요" |
| 5-4 | 전송 완료 | 있음 | 사진 + 기록 / 글만, 두 가지 문구 |
| 6 | 수신함 | 있음 | 새 편지 / 읽은 기록, 사진 있음 / 없음 |
| 7 | 돌아온 하루 | 있음 | 사진 있음 / 없음, 한 줄 답장 입력 |
| 7-1 | 답장 보낸 상태 | 있음 | "보낸 답장" 읽기 전용 |
| 8 | 종료된 이어받기 안내 | 없음 | |

시안이 없는 네 화면(0, 3, 3-1, 8)은 기존 시안의 패턴(큰 제목 + 보조 문구 + 하단 고정 주 버튼)을 따라 만든다. 3-1은 큰 제목, 단계 칩, 질문 말풍선, 카드 미리보기와 메모, 하단 고정 주 버튼("폼에서 다듬기"), 보조 버튼("이대로 카드 받기")으로 구성한다(FE-NFR-02).

화면별 동작과 분기는 `spec/frontend.md` §6에 있다.

## 5.3 디자인 가이드

색상은 시안에서 추정한 값이다. 디자인이 확정되면 토큰 값만 바꾼다(프론트 Q5).

| 토큰 | 값(추정) | 쓰임 |
|---|---|---|
| `--color-primary` | `#234D3A` | 주 버튼, 제목, 로고, 선택된 탭 |
| `--color-bg` | `#FAF8F3` | 화면 배경 |
| `--color-surface` | `#FFFFFF` | 카드, 입력칸 |
| `--color-plan` | `#F4ECDD` | "내가 남긴 계획", 계획자 사연 박스, 경고 박스 |
| `--color-record` | `#E4EDE5` | "방문 기록" 카드, 상태 배지 배경 |
| `--color-accent` | `#F0B86E` | 미확인 점 |
| `--color-danger-bg` | `#F8E8E4` | 사진 처리 실패 아이콘 배경 |

- 모바일 우선이다. 360–480px 폭에서 시안과 같은 배치로 보이고, 더 넓으면 최대 폭 480px로 가운데 정렬한다.
- 레이아웃은 상단 헤더(뒤로가기 + 가운데 제목), 본문, 하단 고정 주 버튼(모서리 12–16px, 꽉 찬 폭), 하단 탭(목록형 화면만)이다.
- 단계 화면은 모두 큰 제목(2줄, 굵게)과 회색 보조 설명으로 시작한다.
- 산책 동선은 번호 원과 세로 연결선으로 된 타임라인이다. 마지막 장소의 번호 원은 채운다.
- 상태 배지는 이어받기 가능 / 이어받음 / 완료 / 공개 / 새 편지 / 읽은 기록이다.
- 완료·확인 화면은 원형 아이콘(체크·느낌표), 제목, 설명, 요약 카드, 하단 버튼으로 구성한다.

## 5.4 캠퍼스 버전에서 동네 버전으로 바뀐 점

두 PDF를 비교한 결과다.

| 항목 | 캠퍼스 버전 | 동네 버전 |
|---|---|---|
| 배경 | 같은 캠퍼스의 선배·후배 | 같은 동네의 계획자·실행자 |
| 예시 인물 | 지민 선배, 서윤 후배 | 지연, 수현 |
| 예시 계획 | 졸업 전, 마지막 캠퍼스 산책 (장소 3곳) | 이사 전, 마지막 동네 산책 (장소 2곳) |
| 둘러보기 버튼 | "내가 보내고 싶었던 하루 남기기" | "취소된 하루 남기기" |
| 계획자 박스 | "지민 선배가 남긴 하루" + 하고 싶었던 일 | "지연 · 취소한 이유" + 취소한 이유 |
| 폼 두 번째 칸 | "남기고 싶은 이유" | "취소한 이유" |
| 장소 입력 | 장소 이름, 하고 싶었던 일 | "이 장소를 고른 이유" 추가. 동선에도 표시 |
| 실행자가 보내는 글 | "편지" | "방문 기록" |
| 작성 화면 버튼 | "사진과 편지 보내기" | "사진과 방문 기록 보내기" + "사진 없이 글로 완료" |
| 보내는 중 | 진행 표시만 | "글로 완료하기" 추가 |
| 사진 실패·교체 | "편지만 보내기" | "글로 완료하기" |
| 이어받기 중단 | "이어받기 취소" | "이어받기 포기". 포기하면 다시 공개된다는 안내 추가 |
| 수신함 | 새 편지 | 새 편지 + 읽은 기록 |
| 답장 후 | 별도 완료 화면("답장을 보냈어요") + 보낸 답장 상태 | 같은 화면에서 "보낸 답장" 읽기 전용으로 전환 |

레이아웃과 색은 두 버전이 같다.

## 5.5 시안과 명세의 차이

시안은 AI 정리 방식을 바꾸기 전에 만들어졌고, 명세가 그 뒤에 더 구체화되었다. 구현할 때 아래 차이를 알고 있어야 한다. 명세와 시안이 다르면 명세를 따르되, 화면 배치는 디자인 담당과 맞춘다.

| # | 차이 | 시안 | 명세 |
|---|---|---|---|
| 1 | 폼(3-2)의 입력칸 | 하루 제목, 취소한 이유, 예상 소요 시간, 산책 동선 | 여기에 하고 싶었던 일 요약(`summary`)과 방문 질문(`question`)이 더 있다. 둘 다 필수다 |
| 2 | 방문 기록 작성(5)의 방문 질문 | 보이지 않는다 | 계획 제목, "{계획자}에게" 라벨과 함께 하루 카드의 방문 질문을 보여 준다 (FE-REC-01) |
| 3 | 예시 장소 이름 | "골목 빵집", "처음 들러 소금빵 사기", "물소리 듣기" | "출근길 빵집", "들러서 빵 사기", "벤치에 앉아 쉬기". 명세에서 "골목 빵집"은 원문에 없는 표현의 예로 쓰인다 |
| 4 | 하루 대표 사진 | 둘러보기 카드와 상세에 커버 사진이 있다 | 이번 일정에서 하지 않는다. 기본 일러스트나 플레이스홀더로 대체 |
| 5 | "편지" 표현 | 사진 교체 화면("작성한 편지는 저장되어 있어요")과 글 전송 완료("편지 전송 완료")에 남아 있다 | 실행자가 보내는 글은 "방문 기록"으로 부른다. 수신함 배지 "새 편지"는 명세에서도 쓴다 |
| 6 | 초안 PDF의 결과 화면 | 데스크톱 형태, "내가 보내고 싶었던 하루 / 누군가 보내고 돌아온 하루", "답장 남기기" | 모바일 2단 카드 "내가 남긴 계획 / {실행자}의 방문 기록", "답장 보내기" |

3번은 목업 데이터와 seed 데이터를 만들 때 영향을 준다. 프론트엔드 MSW의 AI 경로(`?mock=ai-ask`)는 `spec/backend.md` §7.2 예시("출근길 빵집")를 따르도록 정해져 있다. 예시 계획 데이터를 시안과 명세 중 어느 쪽에 맞출지는 정해지지 않았다.
