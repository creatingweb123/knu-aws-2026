# 6. 미결 사항

> 세부 명세: [`spec/backend-requirements.md`](./spec/backend-requirements.md) §7 (Q1–Q21), [`spec/frontend-requirements.md`](./spec/frontend-requirements.md) §7 (Q1–Q9)
>
> 6.1–6.2는 두 요구사항 명세서의 질문을 결정 시점별로 묶은 것이다. 6.3–6.4는 문서 전체를 대조하면서 확인한 내용이다.

질문 번호는 `BE-Q6`, `FE-Q3`처럼 접두어를 붙여 적는다. 두 명세서가 각자 Q1부터 번호를 매기므로 같은 번호가 다른 질문을 가리킨다.

## 6.1 결정 시점별 정리

### 구현을 시작하기 전

| 질문 | 내용 | 제안 |
|---|---|---|
| FE-Q3 | CSS Modules와 Tailwind 중 무엇을 쓸지 | 프론트엔드 1단계 시작 전에 팀 합의 |
| 일정 | 단계별 담당자와 날짜 | 두 개발계획서 6장의 표가 비어 있다. 팀 인원과 기간이 정해지면 채운다 |
| BE-Q15, FE-Q9 | 데모와 시범 운영까지 Docker(에뮬레이터)로 운영할지 | **아니다.** 데모, 시범 운영, 동시성 통합 테스트는 실제 AWS에 SAM으로 배포한다. Docker는 개발과 단위·로컬 통합 테스트용이다. 에뮬레이터로는 JWT authorizer·IAM·알람 같은 AWS 고유 동작이 검증되지 않고, AWS Skill Training의 목적과도 어긋날 수 있다 |

### 백엔드 1단계(로컬 환경 구성)에서 확인

| 질문 | 내용 | 제안 |

| BE-Q17, FE-Q8 | 로컬 인증을 Floci Cognito로 할지 dev JWT로 할지. Floci Cognito ID 토큰에 `nickname` 클레임이 들어가는지, Amplify가 사용자 지정 Cognito 엔드포인트로 로그인할 수 있는지 확인하지 못했다 | Floci Cognito와 시드 사용자를 쓰고, 자동화 테스트는 어댑터의 dev JWT를 쓴다. 프론트엔드에서 안 되면 로컬 백엔드 모드는 `VITE_AUTH_MODE=dev-jwt`로 쓰고 로그인 화면은 `dev` 스택에서 확인한다 |
| BE-Q16 | 로컬에서 실모델을 확인할 때 Ollama를 쓸지 vLLM을 쓸지 | 기본은 Fake 채팅 모델과 외부 호환 API(개발 키)이고 Ollama는 선택이다. Ollama는 `tool_choice`를 지원하지 않고, 맥의 Docker에서는 GPU를 못 쓰므로 네이티브로 설치한다 |

### 백엔드 6a(AI 레벨 0)를 시작하기 전

| 질문 | 내용 | 제안 |
|---|---|---|
| BE-Q6 | LLM 공급자와 모델 확정. 공급자마다 데이터 보존·학습 정책, 처리 국가, 단가, 도구 호출 관련 파라미터 지원이 다르다 | 후보를 정하고 오프라인 평가 15건으로 최종 선택한다. 입력을 제품 개선에 쓰는 무료 티어와 reasoning을 끌 수 없는 모델은 뺀다 |
| BE-Q7, FE-Q6 | 외부 전송 동의 문구와 위치. 개인정보 보호법상 국외 이전 고지·동의 요건(제28조의8)의 적용 범위도 확인이 필요하다 | "AI 정리 요청 시 사연이 외부 AI 서비스(<공급자명>, <처리 국가>)로 전송되고 공급자 정책에 따라 최대 N일 보관될 수 있음"을 동의 문구에 적는다. 화면에서는 사연 입력 화면의 개인 정보 안내 아래에 둔다. 공급자가 정해지면 빈칸을 채운다 |
| BE-Q11 | 선택한 공급자·모델의 단가를 확인하지 못했다 | 공급자 가격 페이지로 확인하고, 공급자 측 사용량 한도와 AWS Budgets 월 알림 금액을 정한다 |
| BE-Q8 | 신규 계정의 Lambda 동시 실행 한도. 한도가 10이면 예약 동시성을 설정할 수 없다 | 계정 한도를 확인하고, 안 되면 HTTP API 경로별 스로틀과 `AiQuota`로 대신한다 |
| BE-Q18 | LangGraph 의존성의 패키지 크기와 콜드 스타트. 압축 해제 약 90–170MB로 추정했고 import 시간은 확인하지 못했다. 에이전트 함수만 별도 requirements.txt를 두는 SAM 빌드 구성도 정해지지 않았다 | 6a(레벨 0 첫 배포)에서 빌드 크기와 Init Duration을 기록하고 메모리(1024MB 시작)를 조정한다 |

### 백엔드 6b(에이전트 그래프)를 시작하기 전

| 질문 | 내용 | 제안 |
|---|---|---|
| BE-Q9 | 선택한 공급자에서 `ChatOpenAI`가 보내는 파라미터가 실제로 동작하는지 (`max_completion_tokens`, usage 반환, `parallel_tool_calls`) | 공급자별로 실측한다. 무시되면 `LLM_EXTRA_BODY`로 보완하고, usage가 없으면 글자 수로 예산을 추정한다 |
| BE-Q19 | interrupt가 걸려 있지 않은 스레드에 재개 명령을 보냈을 때의 LangGraph 동작 | 프로토타입에서 확인한다. 그 전까지 핸들러는 대기 중인 interrupt를 확인한 뒤에만 재개한다 |
| BE-Q20 | 체크포인트(대화 원문)를 READY 뒤 바로 지울지. 지표는 AiSession에 남으므로 디버깅 외에는 필요 없다 | 기본은 TTL 30일 이하. 개인정보 관점에서 READY·FAILED 직후 지우는 안을 6b에서 정한다 |

| BE-Q14 | T22 판정 기준. 인젝션 문장이 사연 안에 있어서 '카페'가 근거 텍스트에 들어간다. 모델이 카페를 넣어도 명사 휴리스틱으로는 걸리지 않을 수 있다 | 지시문을 근거 텍스트에서 뺄지, 기대 결과를 어떻게 판정할지 정한다 |

## 6.3 문서 사이의 불일치

| # | 내용 | 관련 문서 |
|---|---|---|
| 1 | **초안 PDF와 AI 에이전트 권고안은 지금 설계보다 이전 상태다.** 초안은 단발 AI 호출("AI 초안 생성", "AI 카드 확인")과 Amazon Bedrock을 기준으로 쓰여 있고, 권고안은 Bedrock Converse·Global CRIS·Guardrails를 전제로 한다. 현재는 LangGraph와 외부 OpenAI 호환 API다. 초안의 아키텍처 그림에도 Bedrock이 그려져 있다. 제출용 문서를 다시 쓴다면 이 부분을 고쳐야 한다 | `references/` ↔ `spec/backend.md` §4, §7.2 |
| 2 | **시안의 폼에는 `summary`와 방문 질문 입력칸이 없다.** 명세에서는 둘 다 필수 필드다. 방문 기록 작성 시안에도 방문 질문이 보이지 않는다 | [5.5절](./05-design-mockups.md#55-시안과-명세의-차이) |
| 3 | **시안과 명세의 예시 장소 이름이 다르다.** 시안은 "골목 빵집", 명세는 "출근길 빵집"이고, 명세에서 "골목 빵집"은 에이전트가 고쳐야 하는 원문에 없는 표현의 예다 | 동네 시안 ↔ `spec/backend.md` §5, §7.2 |
| 4 | **백엔드 통합 테스트 파일 목록이 두 곳에서 다르다.** 저장소 구조에는 `authz`, `concurrency`, `idempotency`, `photo`, `ai` 다섯 개가 적혀 있고, 시나리오 대응 표에는 `test_claim_lifecycle.py`와 `test_inbox.py`가 더 있다 | `spec/backend-development-plan.md` §2 ↔ §5 |
| 5 | **권고안의 시연 단계 칩과 계약의 `trace` 예시가 다르다.** 권고안은 칩 다섯 개이고, 계약 예시는 도구 호출 단위로 세 단계다. 프론트엔드 명세는 계약 예시를 따른다 | `AI_AGENT_PROPOSAL.md` 7장 ↔ `spec/backend.md` §7.2 |
| 6 | **`GET /me/plans`는 "이번 일정에서 하지 않음"이지만 P1 목록, Lambda 구성 표, §7.1에 남아 있다.** 틀린 것은 아니고, 구현 범위를 볼 때 헷갈리지 않도록 적어 둔다 | `spec/backend.md` §3, §4, §7.1 |
| 7 | **공수 추정이 현재 설계를 다 반영하지 않는다.** P0 증가분 약 6.5인일은 단발 호출에서 에이전트로 바꿀 때의 추정이다. 로컬 개발 환경과 LangGraph 관련 공수는 백엔드 1단계와 6a를 시작할 때 산정하기로 되어 있다 | `spec/backend-development-plan.md` §6 |

## 6.4 문서에 아직 없는 것

- **LLM 공급자와 모델.** 정해지지 않았다(BE-Q6). 동의 문구, 단가, 타임아웃 측정이 모두 이 결정에 달려 있다.
- **시범 운영 대상.** 어느 동네에서 누구를 대상으로 언제 운영하는지, 초기 도입 후보라는 문화공간이 어디인지 정해진 내용이 없다. 시범 운영 목표(5건 중 3건, 완료 건 중 2건 답장)를 측정하려면 필요하다.
- **시범 운영 동의 절차.** 외부 전송 안내 문구의 화면 위치는 제안되어 있지만, 동의를 어떻게 받는지는 없다.
- **팀 구성과 역할.** 문서에 "프론트 담당", "백엔드 담당"으로만 나온다.
- **발표 일정과 제출물 형식.** 90초 시연과 실행 결과 자료의 내용은 정해져 있으나 날짜와 형식은 없다.
- **데모 링크.** 배포 후 기재하기로 되어 있다.
