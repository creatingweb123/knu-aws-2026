# 요구사항: 백엔드·프론트엔드 정합성 (2026-11-27)

## 1. 목적과 범위

최신 프론트엔드(`cf0220e`, 화면 개선안)와 서비스 정의 일반화(`ad58f3f`)를 실제 백엔드와 맞춘다. 기존 백엔드는 다시 만들지 않는다. 이 spec은 **정합성 변경과 그 검증**만 다룬다. 단계별 기능 명세는 `backend-stage*`, `frontend-stage*`가 기준이다.

- 기준: `origin/main` `cf0220e`. 이 작업 시작 전 로컬 `main`은 `f264dbe`였고, fast-forward로 맞췄다.
- 계약 기준: [`docs/03-api-contract.md`](../../../docs/03-api-contract.md). 계약 변경은 승인 전에 확정으로 적지 않는다.
- 로컬 범위: docker compose(Floci, 어댑터, Fake LLM)와 dev-jwt. AWS 배포, 유료 LLM 호출, 실제 Cognito 브라우저 로그인은 범위 밖이다.

## 2. 분류 기준

프론트엔드가 호출하는 API를 다음 여섯 상태로 나눈다(작업 지시 4번).

| 상태 | 뜻 |
|---|---|
| 정상 구현 | 계약과 맞고, 로컬 실제 API 또는 브라우저 흐름으로 확인했다 |
| 부분 구현 | 일부 분기만 실제 API로 확인했고 나머지는 단위·목업 테스트뿐이다 |
| 미구현 | 계약에 있으나 백엔드에 없다 |
| 계약 불일치 | 구현과 계약 문서, 또는 프론트 타입이 다르다 |
| MSW 전용 | 목업에만 있고 실제 API에는 없다 |
| 실행 검증 필요 | 로컬에서 실행하지 못했거나 AWS에서만 확인할 수 있다 |

API별 분류는 [design.md §2](./design.md)에 있다.

## 3. 발견한 불일치와 처리

| ID | 불일치 | 분류 | 처리 |
|---|---|---|---|
| ALIGN-1 | 계획자·실행자 닉네임이 `null`일 수 있는데(BE-Q45) 프론트 타입은 `string`이라, 상세 화면이 `nickname.slice`에서 깨지고 둘러보기 카드가 "의 하루"로 보였다. 브라우저로 재현했다(Cannot read properties of null) | 계약 불일치 | 프론트 타입과 표시를 고쳤다. 백엔드는 저장값이 없으면 `null`을 그대로 낸다 |
| ALIGN-2 | 닉네임 1–20자 규칙이 프론트 사전 검사에만 있고 백엔드(PreSignUp)에는 없다(FE-Q26 "백엔드가 정책을 정하면 맞춘다") | 계약 불일치 | PreSignUp이 같은 규칙으로 거절한다. 배포 전까지는 로컬에서 실행되지 않는다 |
| ALIGN-3 | PreSignUp이 거절하면 Cognito가 `UserLambdaValidationException`을 주는데 프론트가 이 이름을 몰라 일반 실패 문구를 보였다 | 계약 불일치 | 입력값 안내 문구로 매핑했다 |
| ALIGN-4 | `notes[].restore`(FE-Q7·BE-Q13)는 MSW에만 있다. 실제 API에는 원래 값이 없어 "다시 넣기"가 나오지 않는다 | MSW 전용 | 구현은 바꾸지 않는다. 복원 방식은 design.md §4에서 설계하고 승인 대기로 둔다 |
| ALIGN-5 | `GET /claims/{claimId}/record`의 503 `TRY_AGAIN`(BE-Q46)이 계약 §3.4에 없다 | 계약 불일치 | 승인 대기. 구현과 클라이언트 재시도는 단위 테스트로 확인했다 |
| ALIGN-6 | `CardPage` 미리보기가 `<p>` 안에 `<ol>`을 넣어 React가 DOM 중첩 경고를 낸다(AI 흐름 중 콘솔) | 정상 구현(표시) | 화면 디자인을 바꾸지 않으려고 수정하지 않았다. FE-Q28로 기록했다 |
| ALIGN-7 | 상세 화면 안내 "이어받으면 3일 안에"가 문구에 고정되어 있다. 백엔드 기본값도 3일이다 | 부분 구현 | 바꾸지 않았다. 기한 일수를 바꾸면 문구도 함께 바꿔야 한다고 기록했다 |
| ALIGN-8 | 로컬 Floci Cognito는 브라우저 CORS 사전 요청(OPTIONS)에 `Access-Control-Allow-Origin`을 주지 않아 프론트 Cognito 모드 로그인이 막힌다 | 실행 검증 필요 | 에뮬레이터 설정 문제라 고치지 않았다. Cognito 로그인과 `GET /me` 닉네임은 `tests/local/test_local_flow.py`로 API 수준에서 확인한다 |

## 4. 요구사항

**ALIGN-R1 (닉네임 null 표시).** 계획자·실행자 닉네임이 `null`이면 "계획을 남긴 사람"(계획자), "이어받은 사람"(실행자)으로 표시하고, 빈 문자열이나 "null"을 보이지 않는다. 아바타 글자도 기본 표시명에서 뽑는다.
- 인수 기준: 닉네임 없는 계획의 상세 화면이 오류 화면이 아니라 정상 렌더링된다(vitest 회귀, 브라우저 재현 확인).

**ALIGN-R2 (닉네임 길이 검사).** 회원가입 닉네임은 앞뒤 공백을 뺀 코드 포인트 기준 1–20자다. 백엔드 PreSignUp이 이 규칙을 검사하고, 어긋나면 가입을 거절한다.
- 인수 기준: `tests/unit/test_pre_signup.py` 통과. AWS 배포 뒤 가입 거절을 확인한다(미검증).

**ALIGN-R3 (인증 오류 문구).** `UserLambdaValidationException`은 "입력값을 확인해 주세요."로 바꾼다. 원문 메시지는 화면에 쓰지 않는다.
- 인수 기준: `auth.test.ts` 회귀 테스트.

**ALIGN-R4 (실제 API 연동).** 주 흐름(사연 → AI 정리 또는 직접 작성 → 게시 → 둘러보기 → 이어받기 → 내 하루 → 기록 → 전송 → 수신함 → 읽음 → 답장)을 Agent와 Pipeline 두 모드에서 실제 API로 끝까지 돈다. 산책과 비산책 사례를 모두 포함한다.
- 인수 기준: [tasks.md §2](./tasks.md)의 실행 기록.

**ALIGN-R5 (계약 변경 승인).** 프론트 담당 승인이 필요한 변경(nullable 닉네임의 계약 문서 반영, `restore`, 503 `TRY_AGAIN` 계약 반영)은 계약 문서에 확정으로 적지 않고 "승인 대기"로 표시한다.

**ALIGN-R6 (AI 복원, MSW 정책).** 삭제된 장소 복원은 개인정보 보호 정책을 우회하지 않아야 한다. 실제 API에 새 필드를 임의로 추가하지 않는다.

## 5. 제외 범위

- 실제 AWS 배포, `haru-dev`·`demo` 스택 호출, 유료 LLM(Bedrock·외부 게이트웨이) 호출. 이번에 사용한 로컬 실행은 `LLM_PROVIDER=fake`로 강제했다.
- 비산책 사례의 모델 품질 평가. Fake 모델 시나리오로 파이프라인 구조만 확인했다.
- 화면 디자인 변경, 로그인 방식 변경, Cognito 스키마 변경(만든 뒤 바꿀 수 없다).
- 기존 테스트 삭제나 검증 조건 완화.
