# 수동 체크리스트 (7b 4단계)

프론트엔드 7b 단계에서 사람이 직접 확인하는 항목이다. 자동 테스트(`npm test`, `npm run test:integration`)가 잡지 못하는 화면 배치, 키보드 흐름, 두 사용자 동시 흐름을 본다.

관련 문서: [docs/05 화면](../../../docs/05-screens.md), [docs/06 요구사항](../../../docs/06-requirements.md), [docs/07 §7.5·§7.7](../../../docs/07-development-plan.md).

## 1. 준비

| 항목 | 내용 |
|---|---|
| 대상 환경 | `dev` 스택 (`npm run dev -- --mode dev`, `http://localhost:5173`) |
| 브라우저 | Chrome 최신 2개 창 (시크릿 창 1개, 일반 창 1개). 두 창은 서로 다른 계정으로 로그인 |
| 테스트 계정 | 임시 계정을 가입으로 만든다. AWS 계정 이메일은 쓰지 않는다. 예: `it-jiyeon@example.com`, `it-suhyun@example.com`, `it-minjun@example.com` |
| 화면 크기 | DevTools 기기 모드에서 360px, 390px, 480px. 데스크톱 폭에서는 480px 가운데 정렬 |
| 기록 | 각 항목에 ☐ 대신 ☑ 또는 ✗와 날짜, 실패 시 화면 캡처 경로를 적는다 |

### 상태 표시

| 표시 | 뜻 |
|---|---|
| 지금 | 현재 dev 스택과 프론트만으로 확인 가능 |
| 대기 | 백엔드 해당 단계 배포 뒤 확인 (S2–S4 연동 지점) |

## 2. 시나리오 (두 브라우저)

### S1. 가입과 로그인 (지금)

| # | 확인 내용 | 판정 |
|---|---|---|
| S1-1 | 가입 화면에서 닉네임을 비우면 "닉네임은 1–20자로 입력해 주세요." 문구가 입력칸 아래에 보인다 | ☐ |
| S1-2 | 비밀번호 8자 미만이면 "비밀번호는 8자 이상이에요." 문구가 보인다 | ☐ |
| S1-3 | 대문자·숫자 없는 8자 이상 비밀번호는 프론트 검사를 통과하고, Cognito가 거절하면 정책 안내 문구가 보인다 (FE-Q26 결정) | ☐ |
| S1-4 | 정책을 맞춘 비밀번호로 가입하면 인증 코드 없이 바로 로그인된다 (FE-AUTH-02) | ☐ |
| S1-5 | 잘못된 비밀번호로 로그인하면 "이메일 또는 비밀번호가 맞지 않아요." 문구가 보인다 | ☐ |
| S1-6 | 로그인 후 `/me` 응답의 닉네임이 가입할 때 입력한 값과 같다 (DevTools 네트워크 탭) | ☐ |
| S1-7 | 로그인 상태에서 새로고침해도 로그인이 유지된다 | ☐ |
| S1-8 | 로그인하지 않은 상태로 `/plans/new`에 직접 들어가면 로그인 화면으로 이동한다 (`redirect` 보존) | ☐ |

### S2. 둘러보기와 하루 상세 (지금, 목록은 dev `GET /plans` 응답에 따름)

| # | 확인 내용 | 판정 |
|---|---|---|
| S2-1 | 둘러보기 목록이 로딩 중에는 "불러오는 중"을 보여 주고, 빈 목록이면 빈 상태 문구가 보인다 | ☐ |
| S2-2 | 목록 항목을 누르면 하루 상세로 이동하고 뒤로가기 버튼이 둘러보기로 돌아간다 | ☐ |
| S2-3 | 하루 상세의 동선 타임라인과 예상 소요 시간이 보인다 | ☐ |
| S2-4 | 존재하지 않는 계획 주소를 열면 "찾을 수 없어요" 안내가 보인다 (404 `NOT_FOUND`) | ☐ |

### S3. 이어받기 경합 (대기: 백엔드 4단계 배포 후)

| # | 확인 내용 | 판정 |
|---|---|---|
| S3-1 | 두 창에서 같은 하루를 동시에 "이어받기" 누르면 한 명만 성공한다 | ☐ |
| S3-2 | 실패한 창은 "이미 다른 사람이 이어받았어요" 안내를 보인다 (409 `ALREADY_CLAIMED`) | ☐ |
| S3-3 | 자기 계획에는 이어받기 버튼이 나오지 않는다 | ☐ |

### S4. 방문 기록과 완료 (대기: 백엔드 4단계 배포 후)

| # | 확인 내용 | 판정 |
|---|---|---|
| S4-1 | 글을 쓰고 "글로 완료"하면 전송 완료 화면이 보인다 | ☐ |
| S4-2 | 완료 버튼을 여러 번 눌러도 전송 완료가 한 번만 된다 | ☐ |
| S4-3 | 포기 후 이전 화면에서 기록을 저장하면 "이어받기가 끝났어요" 안내가 보인다 (409 `CLAIM_NOT_ACTIVE`) | ☐ |

### S5. 사진 (대기: 백엔드 5단계 배포 후)

| # | 확인 내용 | 판정 |
|---|---|---|
| S5-1 | 사진을 고르면 미리보기가 보이고, 큰 파일은 업로드 전에 막힌다 | ☐ |
| S5-2 | 업로드 중에는 "보내는 중" 화면이 보이고, 처리가 끝나면 전송 완료가 된다 | ☐ |
| S5-3 | 사진 처리가 실패하면 글이 남고 "글로 완료"를 선택할 수 있다 | ☐ |

### S6. 수신함과 답장 (대기: 백엔드 4단계 배포 후)

| # | 확인 내용 | 판정 |
|---|---|---|
| S6-1 | 지연 창의 수신함에 새 편지가 보이고, 헤더에 미확인 표시가 나온다 | ☐ |
| S6-2 | 편지를 열면 읽음 처리되고 미확인 표시가 사라진다 | ☐ |
| S6-3 | 한 줄 답장은 한 번만 보낼 수 있고, 다시 보내면 "보낸 답장" 상태가 된다 (409 `REPLY_ALREADY_SENT`) | ☐ |

### S7. AI 정리 (대기: 백엔드 6a 배포 후)

| # | 확인 내용 | 판정 |
|---|---|---|
| S7-1 | 사연을 입력하고 "AI와 함께 정리하기"를 누르면 단계 칩이 순서대로 켜진다 | ☐ |
| S7-2 | 질문 말풍선의 선택지를 고르면 카드가 나온다 (6b 배포 후 재확인) | ☐ |
| S7-3 | AI 실패 시 사연이 남고 직접 작성 폼으로 넘어갈 수 있다 | ☐ |

## 3. 반응형 (지금)

360px, 390px, 480px 세 폭에서 아래 화면을 확인한다.

| 화면 | 360px | 390px | 480px |
|---|---|---|---|
| 로그인·가입 | ☐ | ☐ | ☐ |
| 둘러보기 | ☐ | ☐ | ☐ |
| 하루 상세 | ☐ | ☐ | ☐ |
| 내 하루 | ☐ | ☐ | ☐ |
| 수신함 | ☐ | ☐ | ☐ |

확인 내용: 버튼과 입력칸이 화면 밖으로 나가지 않는다, 하단 탭과 하단 고정 버튼이 본문을 가리지 않는다, 긴 닉네임과 제목이 줄바꿈된다.

## 4. 키보드 (지금)

| # | 확인 내용 | 판정 |
|---|---|---|
| K-1 | Tab으로 로그인 화면의 모든 입력칸과 버튼에 순서대로 들어간다 | ☐ |
| K-2 | 포커스가 보이는 표시가 항상 있다 | ☐ |

| K-4 | 하단 탭과 뒤로가기 버튼에 접근 가능한 이름이 있다 (스크린 리더에서 버튼 이름이 읽힌다) | ☐ |
| K-5 | 모달이나 안내 박스가 열려 있을 때 포커스가 그 안에 머문다 | ☐ |
